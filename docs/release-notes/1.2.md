# DocumentDB extension for Visual Studio Code v1.2

> **Unpublished draft:** this page describes planned 1.2.0 behavior for review. It is not a
> statement that version 1.2 has shipped, and the text may change before release.

Version 1.2 is planned to make database connections survive routine token renewal and idle drops,
while keeping open views safe when credentials, identities, or connection settings change. It also
adds an explicit Disconnect workflow with clear choices for open tabs.

## What's New in v1.2 (draft)

### ⭐ Connections That Stay Usable

Microsoft Entra ID token renewal is planned to remain silent during normal use. The extension keeps
the connection pinned to the account and tenant that established it, including in the Interactive
Shell and Query Playground. Closed clients and recoverable transient failures can be replaced on a
later foreground operation without restarting VS Code.

When silent sign-in is no longer possible, the extension asks for an explicit action at the surface
where work is happening. The tree offers **Retry sign-in**, while the shell and playground can offer
**Sign in again**. The operation never moves an existing session to a different Microsoft account.

Azure discovery also renews its Azure Resource Manager credentials rather than retaining a frozen
token from an earlier provider tree. This work addresses
[#990](https://github.com/microsoft/vscode-documentdb/issues/990) and
[#1102](https://github.com/microsoft/vscode-documentdb/issues/1102).

See [Keep connections usable](https://microsoft.github.io/vscode-documentdb/user-manual/connecting-to-databases#keep-connections-usable).

### ⭐ Disconnect, Reconnect, and Keep Your Place

Connected clusters gain a **Disconnect** action. Before ending live work, the extension asks what to
do with open view tabs: **Close all** or **Keep open**. A setting can choose either
behavior in advance, while unsaved document changes still require explicit confirmation.

Retained Collection View, Document View, and Cluster Dashboard contents stay available for
inspection or copying under a connection dialog. If **Reconnect** automatically opens the retained
Dashboard for the same connection, the Dashboard retries on its own. If it stays disabled, select
**Retry**, as you would in other retained webviews. Use **Close view** when the connection changed or
was removed. Retry does not replay the operation that failed.

If a tracked copy, export, or import is using the cluster, the task and connection keep running.
Select **Disconnect** again after the task finishes or you stop it. The same teardown rules apply
when a saved connection is deleted, with the additional step of removing its saved
connection and cached credentials. See
[#566](https://github.com/microsoft/vscode-documentdb/issues/566) and
[#1059](https://github.com/microsoft/vscode-documentdb/issues/1059).

Learn how retained views, shells, and playgrounds resume in the
[connection lifecycle guide](https://microsoft.github.io/vscode-documentdb/user-manual/connecting-to-databases#disconnect-and-reconnect).

### ⭐ Open Work Stays Bound to Its Original Connection

Saving changes with **Update Credentials…** or **Update Connection String…**, even just a password,
permanently disables operations in existing Collection View, Document View, and Cluster Dashboard
tabs. You can still copy their contents. Open a new view from the tree to use the saved settings.

Shell and Playground are different: a Shell you choose to leave running can keep its previous
settings, and a restarted worker can use a password-only update without a new terminal or connection
pick. A different host, user, or identity requires a new Shell or an explicit Playground connection
pick.

## Key Limits and Improvements

- **No replay of uncertain writes.** Reconnecting or clicking Retry never resubmits the failed
  operation. Check the server before repeating a write that did not report an outcome.
- **Resume in the same shell or playground.** After reconnecting with unchanged settings, run
  again in the existing terminal or file. Scrollback and query text stay, but worker-local state
  such as variables is lost.
- **Follow-up network work is outside this release.** Kubernetes tunnel recreation and broader
  network resilience remain tracked in
  [#1105](https://github.com/microsoft/vscode-documentdb/issues/1105).
